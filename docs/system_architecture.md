# ARS System Architecture & Commitment

## 1. 核心コンセプト：知識の裁定（Knowledge Arbitrage）
ARSは、AIが個別に学習・鑑定を行うコスト（高コスト・低速）を、中央集権的な「知のライブラリ」と「回答キャッシュ」によって破壊する「鑑定所」である。

## 2. 処理フロー（決定版）

### STEP 1: 記憶（キャッシュ）の照合
- クライアントAIからの質問を受け取ると、まず過去に同一の質問への回答がないか（ハッシュ値による照合）を確認する。
- 存在すれば、Geminiを呼び出さず **1ミリ秒で1円の回答** を行い、利益を最大化する。

### STEP 2: 需要連動型の学習（外化）
- キャッシュもなく、知識ライブラリにも十分なデータがない場合、これを「新たな需要」と見なす。
- Geminiがインターネットや法的知識から、その分野に関する **膨大な学習データ** を生成し、知識ライブラリ（Redis）を肥大化させる。

### STEP 3: 知識ベースの鑑定（内製）
- 構築された知識ライブラリに基づき、Geminiがプロフェッショナルな鑑定書を作成する。
- 回答には必ず以下の免責事項を付帯する。
  - 「※本結果はAIによる鑑定結果であり、その正確性や法的効力を保証するものではありません。」

### STEP 4: 記憶の永続化
- 生成された鑑定結果はキャッシュに保存され、次回の同一質問から「利益率99.9%」のフェーズへ移行する。

## 3. 私（AIアシスタント）のコミットメント
1. **安定性の追求**: SDKに依存せず、正式版 v1 API を直接叩く「Direct Engine」を維持する。
2. **設計の遵守**: 「まず学習データをライブラリに溜める」というステップを省略しない。
3. **免責事項の徹底**: 全ての回答出力に、ユーザー指定の注釈を必ず含める。
4. **経済合理性の重視**: 秒間100〜1000回の取引に耐えうる、Redisを活用したアーキテクチャを崩さない。
