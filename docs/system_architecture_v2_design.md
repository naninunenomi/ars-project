# ARSシステム設計案 v2：高耐久・自律学習エンジン

## 1. 目的
本設計は、システムの安定性（フリーズ防止）と、外部からの大量の需要に対する自律的な学習・適応を両立させることを目的とする。

---

## 2. コア・アーキテクチャ：非同期「付箋（キュー）」方式

### ① 鑑定窓口 (`api/check.js`) - 【最速の回答】
- **役割**: 外部AIからのリクエストに対し、キャッシュまたはGeminiを用いて即座に鑑定結果を返す。
- **学習連携**: ライブラリにない未知のテーマ（例：新しい規制）を検知した場合、その場で学習は行わず、Redisの「学習待ちリスト (`ars_learning_queue`)」にテーマ名を書き込む（付箋を貼る）。
- **メリット**: 回答速度を最大化し、自身の負荷を最小限に抑える。

### ② 自律店長 (`api/autopilot.js`) - 【安全な成長】
- **役割**: 定期的に起動し、市場監視と「学習待ちリスト」の消化を行う。
- **安全装置 (Brake)**:
    - **クールダウン**: `ars_autopilot_last_run` を確認し、設定時間（例：10秒）以内であれば即座に終了。
    - **逐次処理**: 1回の起動につき、リストから1つのテーマのみを取り出して学習。一括処理によるメモリパンクを防止。
- **学習処理**: 取り出したテーマに基づき、Geminiを用いて公的データやWeb上の情報を集約・要約し、「知識ライブラリ (`ars_knowledge_base`)」を更新する。

---

## 3. データ構造 (Redis/KV)

| キー名 | 形式 | 役割 |
| :--- | :--- | :--- |
| `ars_learning_queue` | List | 未学習トピックの行列（付箋の束） |
| `ars_knowledge_base` | Hash | 学習済みの専門知識（事務所の蔵書） |
| `ars_autopilot_last_run` | String | 最後に店長が動いた時刻（タイムカード） |
| `ars_daily_stats` | Hash | 収益、取引件数の統計データ |

---

## 4. 成長のサイクル

1.  **遭遇**: 外部AIが「未知の法律」について質問。窓口が鑑定し、付箋を貼る。
2.  **待機**: 付箋がリストに溜まる。
3.  **学習**: 店長が10秒に一度、付箋を1枚手に取り、深く勉強してライブラリに保存。
4.  **資産化**: 次に同じ質問が来た時、窓口はライブラリを見て「原価0円」で即答する。

---

## 5. 監督（ユーザー）へのメリット
- PCの動作が常に安定し、バックグラウンドでの「勝手な成長」を安心して見守ることができる。
- 学習頻度を制御できるため、APIコストの爆発を防げる。
