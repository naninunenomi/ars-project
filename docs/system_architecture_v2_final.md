# ARSシステム最終設計図 v2.2（完全版）

## 1. 鑑定窓口 (`api/check.js`)：収益の最大化
- **リアルタイム記帳**: 取引完了と同時に `ars_total_revenue` を更新（INCR）。監督は常に最新の収益を把握可能。
- **需要検知（付箋）**: 未知の法律テーマを検知した場合、`ars_learning_queue` に追加。自らは鑑定処理を最優先し、遅延を最小化する。

## 2. 自律店長 (`api/autopilot.js`)：安定と成長の両立
店長は10秒に一度起動し、以下の「知的ルーチン」を順番に実行する。

### ① 市場監視（1秒のチラ見）
- **動作**: 毎回の起動時、SNSや公的サイトのヘッドラインを簡易スキャン。
- **目的**: 最新トレンドや緊急の法改正の兆候を掴み、必要なら「学習待ちリスト」へ追加する。

### ② 運営モードの自動切替
- **メンテナンス・モード (24h毎)**:
    - ライブラリ全件の鮮度を点検。変化があれば更新し、なければ「点検済み」と記録。
    - 全項目の点検が完了するまで、新規学習は一時停止する。
- **通常モード（学習・収益）**:
    - メンテナンス完了後、溜まった「学習待ちリスト」をリレー方式（1回1ステップ）で処理。
    - 収益統計の最終確認を行い、ダッシュボードを最適化する。

## 3. 安全・安定・不休の設計
- **フリーズ防止**: 10秒の実行インターバルを強制。ブラウザの過剰なリクエストからシステムを守る。
- **タイムアウト回避**: Deep Researchを「調査設計」「各URL読込」「統合」のステップに分割。Vercelの10秒制限内で確実に動作させる。
- **非同期・独立動作**: 鑑定窓口と店長の処理を完全に分離。店長がどんなに複雑な学習をしていても、窓口の1円取引は一切影響を受けない。

---

## 4. 監督のスキームの具現化
- **「10円 vs 1円」の経済的独占**: 高鮮度・高精度のライブラリを安価に提供し、外部AIをARSへ依存させる。
- **「複利的な知識の成長」**: 寝ている間も店長が知識を積み上げ、原価0円の利益源を自動で増設し続ける。
